Test page

Address lookup component test

A standalone harness for the HPD lookup. It calls the same vendored @howellandgibbs/hpd-lookup package the live site calls, but shows HPD's raw data next to the parsed output so the parser can be spot-checked against real buildings.

How to test

This page imports an ES module, so it must be served over HTTP — run python3 -m http.server 8000 from the repo root and open it from localhost. It will not run from a file:// URL.

  1. Type an NYC address in the input below. Try a known-good one like 250 Ocean Pkwy, Brooklyn or your own NYC address.
  2. Suggestions should appear as you type (after ~3 characters). Click one.
  3. The page queries HPD violations for that building and displays them below.
  4. Read the debug panel at the bottom. For the first few violations it prints HPD's raw novdescription and currentstatus directly above what the parser made of them, so you can see whether the citation chain was stripped correctly and the status was read the right way.
  5. Any status the package does not recognize is flagged there explicitly rather than guessed at. Those belong upstream in howellandgibbs/hpd-lookup, not here.
  6. If a request fails, the debug panel shows the error code the package raised and the page falls back to a link-out to HPDOnline.

Reach for this page after scripts/update-hpd-lookup.sh bumps the vendored bundle, to confirm a new build still reads HPD's text the way you expect.

You can also try a single status string from the browser console without doing a full lookup — for example checkStatus('INVALID CERTIFICATION'), which should come back open, not dismissed.

This page looks up all violations and applies no keyword filter. The scenario pages narrow results to scenario-specific violations (mold for mold, pests for pests) via initLookup({ filterKeywords }) in lookup.js, which this page deliberately does not load.
